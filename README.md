# Geo Analytics Pipeline

ETL-пайплайн для обработки событий пользователей социальной сети, географического обогащения данных и формирования аналитических витрин с использованием Apache Spark и Apache Airflow.

## О проекте

Проект реализует обработку пользовательских событий социальной сети и подготовку данных для геоаналитики.

Входные данные содержат события пользователей с координатами, временными метками и различными типами взаимодействий: сообщения, подписки и реакции.

В рамках проекта реализован pipeline, который:

* извлекает события из Parquet;
* унифицирует идентификаторы пользователей и временные поля;
* определяет ближайший к пользователю город по географическим координатам;
* рассчитывает расстояние между координатами с использованием формулы Хаверсина;
* определяет актуальный и домашний город пользователя;
* рассчитывает статистику перемещений пользователей;
* формирует агрегаты пользовательской активности по географическим зонам;
* строит витрину для рекомендаций друзей на основе общих подписок и географической близости;
* сохраняет результаты в формате Parquet;
* запускает обработку и управляет зависимостями между Spark jobs через Apache Airflow.

## Основные задачи

### 1. Географическое обогащение событий

Для каждого пользовательского события определяется ближайший город на основании координат.

Расстояние между координатами пользователя и города рассчитывается по формуле Хаверсина.

Для поиска ближайшего города используется оконная функция:

```text
user event → coordinates → distance to cities → nearest city
```

Справочник городов используется как broadcast dataset, что позволяет избежать полноценного shuffle при присоединении небольшого справочника.

### 2. User Geo Mart

Формируется пользовательская витрина со следующими характеристиками:

* текущий город пользователя;
* домашний город;
* количество поездок;
* последовательность посещённых городов;
* локальное время последнего события.

Домашний город определяется на основании непрерывного пребывания пользователя в городе не менее 27 дней.

Для анализа последовательности событий используются оконные функции `LAG`, `ROW_NUMBER` и агрегирование по группам непрерывного пребывания.

### 3. Zone Geo Mart

Формируется агрегированная витрина активности пользователей по географическим зонам.

Рассчитываются:

* количество сообщений;
* количество реакций;
* количество подписок;
* количество новых пользователей.

Показатели формируются на недельном и месячном уровнях.

Это позволяет использовать одну витрину для последующего анализа пользовательской активности в различных географических зонах.

### 4. Friend Recommendation Mart

Формируется витрина потенциальных рекомендаций друзей.

Алгоритм:

1. определяются пользователи, подписанные на один и тот же канал;
2. формируются уникальные пары пользователей;
3. исключаются пары, которые уже обменивались сообщениями;
4. для пользователей определяются последние координаты;
5. рассчитывается расстояние между пользователями;
6. остаются пары, находящиеся на расстоянии не более 1 км.

В результате формируется витрина с потенциальными парами пользователей для дальнейшего использования в рекомендательной логике.

## Оркестрация

Apache Airflow используется для управления последовательностью выполнения Spark jobs.

DAG `geo_analytics_pipeline` запускает три задачи:

```text
build_user_mart
      │
      ├──────────────► build_zone_mart
      │
      └──────────────► build_friend_rec_mart
```

Сначала строится пользовательская витрина, после чего параллельно запускаются витрины географических зон и рекомендаций друзей.

Для запуска Spark jobs используется `SparkSubmitOperator`.

В DAG также настроены:

* расписание запуска;
* retry при ошибке;
* задержка между повторными попытками;
* параметры памяти Spark driver и executor;
* зависимости между задачами.

## Результат

В результате реализован воспроизводимый ETL-пайплайн, который преобразует исходные пользовательские события в набор специализированных аналитических витрин:

```text
Raw events
    ↓
PySpark ETL
    ↓
Geo enrichment
    ↓
┌──────────────────┬──────────────────┬────────────────────┐
│ User Geo Mart    │ Zone Geo Mart    │ Friend Rec Mart    │
└──────────────────┴──────────────────┴────────────────────┘
```

Полученные витрины подготовлены для дальнейшего использования в задачах пользовательской и географической аналитики, а также рекомендательных сценариях.

## Запуск

Перед запуском необходимо настроить:

* Apache Spark;
* Apache Airflow;
* Spark connection в Airflow;
* пути к исходным данным;
* пути сохранения результирующих витрин.

DAG запускается через Apache Airflow.

Spark jobs могут запускаться отдельно с параметром выборки:

```bash
python user_mart.py --sample 0.1
python zone_mart.py --sample 0.1
python friend_rec_mart.py --sample 0.1
```

Параметр `--sample` позволяет использовать часть исходных данных для тестового запуска.

## Ключевые инженерные решения

* Использование Apache Airflow для оркестрации нескольких Spark jobs.
* Разделение обработки на отдельные этапы и аналитические витрины.
* Повторное использование общей логики географического обогащения через `UserGeoProcessor`.
* Использование оконных функций для определения последних событий, последовательности перемещений и непрерывных периодов пребывания.
* Использование broadcast join для справочника городов.
* Использование `left_anti join` для исключения уже существующих связей между пользователями.
* Поддержка тестового запуска на выборке данных через параметр `--sample`.
